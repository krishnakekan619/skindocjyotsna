# Decision Log

Decisions confirmed by the product owner. Newest first. Each entry refers back to `DESIGN-v2-desktop.md` where relevant.

| ID | Date | Decision | Notes / consequences |
|---|---|---|---|
| DEC-020 | 2026-09-25 | **Setup roles: Dev reuses existing tools; Build requires exact locked versions.** Dev: an installed tool ≥ the minimum in `versions.env` is kept. Build: Node.js and Rust must equal `tools.lock`; a different version stops setup and is never silently replaced. `build-release.mjs --release` enforces the same rules plus strict lock checks, and writes `BUILDINFO-<os>.txt`. | New `Install-BuildPC.cmd` / `Install-BuildMac.command`. Git, Build Tools and WebView2 follow the minimum rule in both roles (they don't change the app's output). |
| DEC-019 | 2026-09-25 | **Everything is pinned in lock files with checksums.** Tools: `setup/<os>/tools.lock`, created from the newest stable releases on the first Prepare run and updated only with `-UpdateLock`. Project: `package.json` pins exact versions (`.npmrc save-exact`), and `package-lock.json` / `Cargo.lock` pin every transitive package. `scripts/check-locks.mjs` rejects pre-releases and missing checksums. | Keeps every build traceable and reproducible. Evergreen vendor links (WebView2, VS bootstrapper) now fail loudly when the vendor changes the file, instead of silently changing. |
| DEC-018 | 2026-09-25 | **Minimal Visual Studio Build Tools:** only `VC.Tools.x86.x64` (MSVC compiler and linker) + `Windows11SDK.26100`, instead of the full C++ workload with recommended components. | Both component IDs verified in Microsoft's current catalog (Build Tools 17.14.41). Configurable via `VS_COMPONENTS` in `versions.env`. |
| DEC-017 | 2026-09-25 | **One OS login on the clinic PC, two app logins:** owner = `ADMIN`, reception = `RECEPTIONIST`. | Resolves Q-P2: data stays in that OS account's app folder, with no shared folder needed. Staff are told apart by their SkinDocJyotsna login (Phase 1). |
