# Decision Log

Decisions confirmed by the product owner. Newest first. Each entry refers back to `DESIGN-v2-desktop.md` where relevant.

| ID | Date | Decision | Notes / consequences |
|---|---|---|---|
| DEC-028 | 2026-09-26 | **Billing scope for v1** (deviations from design): (a) discounts are bill-level only (none / percent / rupees), allocated to lines by largest remainder; no per-line discounts. (b) A bill being typed is kept in screen memory, not saved as a DB draft (design D15); it is lost if the app closes before Finalize. (c) CSV export of reports is deferred; reports can be printed. (d) Correction works on the whole bill (cancel + reissue, DEC-001); receptionists may correct only same-day bills, older ones need an admin. (e) Returns after the return window (default 7 days) need an admin. | Finalize is idempotent: a repeated request with the same key returns the saved bill. Stock is never negative; short lines are recorded as not supplied (DEC-002/007). |
| DEC-027 | 2026-09-26 | **Schema details for Phase 1** (deviations from design §7): timestamps are `INTEGER` Unix seconds UTC rather than ISO text (simpler lockout arithmetic, compact, sortable; the UI formats them). Roles are a checked `role` column (`ADMIN`/`RECEPTIONIST`) rather than a separate `role` table, because there are exactly two fixed roles. The user table is `app_user`. New crate `clinic-services` holds the application flows (between `clinic-core` rules and `clinic-sqlite` storage). | Admin changes re-check the acting user inside the transaction, so a stale session loses its powers as soon as its user is deactivated or demoted. |
| DEC-026 | 2026-09-26 | **English-only UI and receipts.** All UI text lives in one module (`src/i18n/en.ts`), so a language can be added later without touching screens. | |
| DEC-025 | 2026-09-26 | **Password recovery = second admin account** (no recovery code). Either admin can reset the other's password/PIN. The last active admin can never be deactivated or demoted. First-run setup offers creating the second admin (e.g. the doctor); until one exists, admins see a persistent warning. | Supersedes design Q16 default. With only one admin and a forgotten password, the fallback is restoring from backup. |
| DEC-024 | 2026-09-26 | **Idle lock after 15 minutes** (setting, 5–60 min). Enforced in the Rust shell as well as the UI: a command after the idle time returns "locked". | |
| DEC-023 | 2026-09-26 | **Unlock with a personal 4–6 digit PIN**; the full password is needed at app start. The PIN is hashed (Argon2id) like the password; 5 wrong PINs disable PIN unlock until the full password is entered. | |
| DEC-022 | 2026-09-25 | **Clinic PCs install prebuilt installers from GitHub; they never build.** Pushing tag `vX.Y.Z` publishes a permanent GitHub Release (installers, `.sha256`, `BUILDINFO`, `SHA256SUMS`; the tag must match `package.json`). `scripts/import-release.mjs` verifies downloaded installers and adds them to an offline bundle for `Install-ClinicPC.cmd` / `Install-ClinicMac.command`. | Build artifacts (14-day retention) are for testing only. Only the release job has write permission. Installers stay unsigned until Q15. |

Repository: **private, on the owner's personal GitHub account**, all work committed **directly to `main`** (owner's choice; supersedes DEC-009 "no git yet"). | UI work (`npm run web:dev`) still runs locally. The unsigned app cannot run on this laptop, so manual app testing needs another PC. CI uses the Node/Rust versions from `tools.lock`. The no-admin Rust option stays for unmanaged PCs without admin rights. |
| DEC-020 | 2026-09-25 | **Setup roles: Dev reuses existing tools; Build requires exact locked versions.** Dev: an installed tool ≥ the minimum in `versions.env` is kept. Build: Node.js and Rust must equal `tools.lock`; a different version stops setup and is never silently replaced. `build-release.mjs --release` enforces the same rules plus strict lock checks, and writes `BUILDINFO-<os>.txt`. | New `Install-BuildPC.cmd` / `Install-BuildMac.command`. Git, Build Tools and WebView2 follow the minimum rule in both roles (they don't change the app's output). |
| DEC-019 | 2026-09-25 | **Everything is pinned in lock files with checksums.** Tools: `setup/<os>/tools.lock`, created from the newest stable releases on the first Prepare run and updated only with `-UpdateLock`. Project: `package.json` pins exact versions (`.npmrc save-exact`), and `package-lock.json` / `Cargo.lock` pin every transitive package. `scripts/check-locks.mjs` rejects pre-releases and missing checksums. | Keeps every build traceable and reproducible. Evergreen vendor links (WebView2, VS bootstrapper) now fail loudly when the vendor changes the file, instead of silently changing. |
